# EarthStep 開発タスク一覧

仕様書: [docs/spec.md](./spec.md)

本ドキュメントは仕様書を実装単位のタスクへ細分化したもの。
タスクIDは `フェーズ番号-連番` 形式。見積もりは1人日=8hの目安。

## 想定技術スタック(前提)

| 項目 | 選定 |
|---|---|
| 言語 | Kotlin |
| UI | Jetpack Compose |
| DI | Hilt |
| 非同期 | Coroutines / Flow |
| DB | Room |
| 設定保存 | DataStore (Preferences) |
| 位置情報 | Google Play Services Location (FusedLocationProvider) |
| 活動検知 | Play Services ActivityRecognition + Activity Transition API |
| 常駐 | Foreground Service (`foregroundServiceType="location"`) |

### P1 の実装メモ

| 決めたこと | 理由 |
|---|---|
| 日別距離の加算は `INSERT OR IGNORE` + `UPDATE ... SET distance_m = distance_m + ?` の2文 | SQLite の UPSERT (`ON CONFLICT ... DO UPDATE`) は 3.24 以降。minSdk 26 (Android 8.0 = SQLite 3.18) では使えない。2文をリポジトリのトランザクションで束ねる |
| `lifetime_stats` は `id` 固定の単一行 | 更新系をすべて UPDATE 文で書けるようにするため。行が無い場合は更新前に `INSERT OR IGNORE` で作る |
| 時刻・タイムゾーンは `AppTimeSource` 経由でのみ取得 | 日付境界をテスト可能にするため。タイムゾーンは実行中に変わるのでキャッシュしない |
| 当日距離の Flow は `DayTicker` で日付変更時に張り替え | 深夜0時に加えて最大1時間ごとに再確認し、タイムゾーン変更も拾う |
| マイルストーンの一言説明は `description: String?` として型を先に用意 | P1時点では文面が未執筆で全件 null。文面は P10-2(2026-08-22)で全100件執筆済み |
| 達成の冪等化は PK + `OnConflictStrategy.IGNORE` | P4-3 の前倒し。DAO 側で二重記録が起きない状態にしておく |
| Room のスキーマJSONは `app/schemas/` へコミット | `SchemaExportTest` がバージョンとテーブル数を検証し、出し忘れをCIで落とす |

### P2 の実装メモ

| 決めたこと | 理由 |
|---|---|
| 棄却した区間では起点(アンカー)を進めない | これだけで仕様1.5の3点整合性チェック(A→B→C で B が外れ値なら A→C)が特別扱い無しに成立する。低精度点を挟んでも直線の距離が失われない |
| 加算した距離は3秒寝かせてから確定させる | 停止確定時の遡及除外(仕様1.4)を「DBへ書いた距離を後から引く」処理無しで実現するため。停止が確定したら窓の中の距離を捨てるだけでよい |
| 起点の保持は20秒まで | それを超える欠測は歩数フォールバックの担当。GPSで直線を引くとトンネル区間が二重計上になる |
| 距離を作るのは常にGPS・歩数のどちらか一方だけ | モードが変わる瞬間に両方の起点を捨てることで、切り替え点をまたぐ区間がどちらでも加算されない(P2-16) |
| 距離はm未満の端数を持ち越して整数で永続化。計測終了時のみ四捨五入 | 5秒ごとの加算で丸め誤差が積もらないようにするため |
| 活動判定は `ON_BICYCLE` / `IN_VEHICLE` を明示的に除外し、`STILL` / `UNKNOWN` では判定を変えない | 静止は速度と歩数を見る停止判定(仕様1.4)の方が確実なため |
| 計測エンジンは入力を1本の `MeasurementInput` 列へ束ねる | 位置・歩数・活動判定が非同期に届くため、個別に状態を持つと到着順に依存したバグが出る |
| ActivityRecognition のレシーバは動的登録 | 計測していない間に起こされても捨てるだけなので、マニフェストへ静的登録すると無駄に電力を使う |

> マニフェストには `ACCESS_FINE/COARSE_LOCATION` と `ACTIVITY_RECOGNITION` のみ追加した。
> 背景位置・フォアグラウンドサービス・通知の各権限は P3-2 で追加する。
> 実際に権限をリクエストする導線(P3-3)がまだ無いため、この時点では実機で計測は動かない。

### P3 の実装メモ

| 決めたこと | 理由 |
|---|---|
| 版数ごとの必要権限は `PermissionRequirements.requiredOn(sdkInt)` に集約 | SDK 版数を引数に取る純粋関数にすることで、実機やエミュレータ無しで各バージョンの分岐をテストできる |
| 背景位置は Android 11 以降だけ設定画面へ誘導 | Android 10 はシステムダイアログで直接聞ける。版数で分岐せずに常に設定画面へ送ると、Android 10 で余計な手間が増える |
| オンボーディングは全ページをスキップ可能にした | 権限を拒否しても縮退して動く設計のため。拒否された状態はホームの警告(P3-9)で常時提示する |
| 常駐通知は 10m 刻みでのみ更新 | 1m ごとに更新すると歩いている間じゅう通知を書き換えることになる |
| サービス停止は `stopService` を使う | 停止用の intent を `startService` で投げる方法は Android 8 以降のバックグラウンド起動制限にかかりうる。`stopService` なら制限を受けず、`onDestroy` 経由で寝かせていた距離も書き切られる |
| 計測開始前に必ず権限を確認する | Android 14 以降、位置情報の権限が無い状態で location 型の FGS を開始すると `SecurityException` で落ちる |
| ホームの警告は「位置情報が無い」ときに背景位置の警告を重ねない | まず「測れない」を直してもらう。同時に何行も出しても読まれない |

**P3-6 の制約**: 確定した距離は都度DBへ書いているため、プロセスを強制終了されても失われるのは
遡及除外バッファに入っている最大3秒ぶん(徒歩なら数メートル)に限られる。この範囲は
「二重計上を避けるために確定を遅らせている」ぶんなので、永続化せず破棄する方が安全と判断した。
歩数センサーの基準値と歩幅は DataStore / DB に永続化済みで、サービス再生成時に読み直す。

**未検証**: 実機・エミュレータでの動作確認は行っていない。常駐の実挙動、権限ダイアログの遷移、
再起動後の復帰は P8(品質保証・実機検証)で確認する。

| 距離が増える経路を `RecordDistanceUseCase` の1本にまとめた | 計測エンジンが `ProgressRepository.addDistance` を直接呼ぶと、達成判定を通らない距離が生まれる |
| マイルストーンは「範囲」ではなく「累計に届いていて未記録のもの」で判定 | プロセスが落ちて判定を1回飛ばしても、次の更新でまとめて拾える。1回の更新で複数達成(P4-2)も自然に処理できる |
| 周回数は累計距離から毎回計算し直す | カウンタを+1する持ち方だと、取りこぼしや二重処理で累計距離と周回数がずれたまま戻らなくなる。累計距離を唯一の真実にすれば何度計算しても同じ答えになる |
| 周内マーカーは永続化しない | 演出のための通知だけが目的。取りこぼしても次の周で出る |
| 進捗率は「直前のマイルストーンから次まで」の区間で測る | 累計距離を次の距離で割ると、序盤の間隔が狭い区間でバーがほとんど動かないように見える |
| マイルストーン一覧の表示可否は「未達成が残っているか」で判定 | 100個目の到達と1周の走破が同じ距離なので結果は同じだが、達成状況を直接見る方が意図が読める(P4-7) |
| 周回スキンは色を使い切ったら先頭へ戻す | 素材は8種類。色が足りないことでクラッシュさせるより、見た目が一巡する方が害が小さい(仕様4.3 の「余力に応じて増減可」) |
| 地球一周の距離を `Earth.CIRCUMFERENCE_METERS` へ一本化 | マイルストーン#100 と周回の1周が同じ値。2か所に持つとどちらかだけ直す事故が起きる |

**周内マーカーの距離**: 仕様4.2 は約10,019 / 20,038 / 30,056km と丸めた値だが、
実装は 40,075km の厳密な 1/4・1/2・3/4(10,018.75 / 20,037.5 / 30,056.25km)を使う。

### P7-1〜P7-5 の実装メモ

| 決めたこと | 理由 |
|---|---|
| JSONの読み込みは寛容に、書き出しは厳密に | 手で編集されたJSONや将来フィールドが増えたJSONを読めなくして記録を丸ごと失わせるより、読める範囲で受け入れる方が損失が小さい |
| `schema_version` は既定値でも必ず書き出す | 省略されると読み込む側が形式の版数を判定できない。`encodeDefaults = true` で強制する |
| 新しい版数のJSONは読み込まずに知らせる | 内容を推測して取り込むと壊れた状態になりうる。版数の判定を最初に行い、部分的な取り込みを防ぐ |
| インポートは上書きではなく必ずマージ | 機種変更でも同期でも「両方の端末で歩いた分を残す」のが目的 |
| 累計距離は日別ログの合計から再計算 | 端末ごとの累計値を信じると、片方が壊れていたときに引きずられる |
| 周回数は再計算した累計から導く | P4 と同じく累計距離を唯一の真実にする |
| DBへの書き戻しは差分適用でなく総入れ替え | マージの結果は「あるべき全体像」。部分的に足すと、マージで負けた側のレコードが残る |
| 歩幅はより多く歩いた側の値を採る | 歩幅はGPS区間の実績から少しずつ較正されるため(P2-14)、歩いた距離が長い側の方が本人の歩幅に寄っている |
| 読めない日時は 0 として扱う | 日時が1件おかしいだけでインポート全体を失敗させるより、距離を守る方を優先する |

**仕様6.3 との差分**: `milestone_achievements` に `distance_m_at_achievement` を追加した。
仕様の例では省略されているが、DBスキーマ(仕様6.1)が持つ列であり、
書き出さないと機種変更で失われる。読み込み時に無ければ、そのマイルストーンの閾値距離で埋める。

**過小評価の範囲(P7-5 で検証)**: 同じ日に2台で別々に歩いた場合、その日は多い方だけが残る。
実測 5,000m と 4,000m なら合計 9,000m ではなく 5,000m になる。
二重計上は一度起きると取り消せず、マイルストーンも周回も先に進んでしまうため、
「少なく数える」側へ倒している(仕様6.4 のトレードオフどおり)。

| `CrashlyticsLogTree` を新設し、既存の `DebugTree`/`ReleaseLogTree` と並行してplant | クラッシュ(未捕捉例外)はSDKが自動収集するが、それとは別にWARN以上のTimberログ・捕捉済み例外もCrashlyticsの非致命的ログとして残したかったため。既存のTreeを差し替えるのではなく追加する形にして、既存のログ方針(P0-6)への影響を避けた |

**実機検証済み(2026-08-22, Pixel 9a)**: `adb shell am crash` で強制クラッシュさせ、次回起動時に
Crashlyticsが検知して `crashlyticsreports-pa.googleapis.com` へアップロードするログを確認。
クラッシュ後もMeasurementServiceがフォアグラウンドへ自動復帰すること(P3-6)も併せて確認できた。

### P10 の背景

- 1〜4: 建物の高さやトンネルの長さなど、実在物の「世界一」「世界2位」等の順位は新しい建造物が現れるたびに変わる。マイルストーン名称に固定で書き込むと将来的に誤情報になるため、名称からは削除し、変わりうる順位情報は達成記録の説明文側に「2026年現在」と時点を明示して残す。
- 5〜XPは現状「消費先がなく、結局は累計距離と同じ数字の別表現」になってしまっているため、ホーム画面の表示からは外す。将来スキンや特典との交換機能を作る可能性があるため、内部の集計自体は止めない。

### P10 の実装メモ

| 決めたこと | 理由 |
|---|---|
| 括弧書きは順位表現以外(通称・区間・限定条件など)も含めて全て名称から外し、説明文側に活かした | 例: #31「淡路島一周(あわいち)」→名称は「淡路島一周」、説明文に「サイクリストの間では『あわいち』と呼ばれます」。情報を失わずに名称だけシンプルにするため |
| 「2026年現在」は人工物の記録(ビル・トンネル・橋・道路・運河・鉄道路線など、将来新しい建造物に抜かれうるもの)にのみ付け、自然地形・国境などの記録(川の長さ、山脈の長さ、国境線の長さ等)には付けなかった | 自然地形や国境は人間の建造物と違って「時の経過で追い抜かれる」性質のものではなく、書き換えても実情と乖離しにくいため。ユーザーへの確認で「人工物のみ」と決定 |
| #4 CNタワーは「2026年現在」ではなく「2007年に抜かれるまで世界一高い自立式建造物でした」と過去形で記述 | 名称にあった「旧世界一」がすでに過去の事実であるため、現在時点を明示する言い回しよりも歴史的事実として書く方が正確 |
| #32・#93 は括弧ではなく地の文に順位表現が埋め込まれていた(「世界最長の橋・丹陽-昆山グランドブリッジ」等) | 同様に名称から外し、地名や路線名だけのシンプルな名称にした |
